# Connecting Amazon S3

Archives clip video to a bucket you own, using static access keys — no OAuth
dance, no redirect URI to configure. This is the simplest of the three
providers to set up.

## 1. Create a bucket

In the [AWS Console](https://console.aws.amazon.com/s3/), create a bucket
(any region) to hold archived clips. Nothing special is required — default
settings (private, versioning off) are fine. Note the bucket name and region;
you'll need both.

## 2. Create an IAM user with a least-privilege policy

Create an IAM user (or role, if you're running this from an EC2 instance/ECS
task and prefer instance credentials over static keys) with a policy scoped
to exactly this bucket and exactly the actions the app actually calls:

```json
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Sid": "BlinkClipsArchive",
      "Effect": "Allow",
      "Action": [
        "s3:PutObject",
        "s3:GetObject",
        "s3:DeleteObject",
        "s3:ListBucket"
      ],
      "Resource": [
        "arn:aws:s3:::YOUR-BUCKET-NAME",
        "arn:aws:s3:::YOUR-BUCKET-NAME/*"
      ]
    }
  ]
}
```

What each action is actually for:

- `s3:PutObject` / `s3:GetObject` / `s3:DeleteObject` — uploading, downloading
  (including presigned links), and deleting clip video during archive/
  restore.
- `s3:ListBucket` — required for the Storage tab's folder browser (listing
  and creating "folders", which S3 represents as zero-byte objects with a
  trailing `/` key) and for the "Test connection" button, which calls
  `HeadBucket` under the hood. Both `ListObjectsV2` and `HeadBucket` are
  authorized by `s3:ListBucket`, not by an action with either of those names
  — a common point of confusion, since IAM's action names don't always match
  the API operation names 1:1.

Nothing broader than this is needed: no `s3:*`, no account-wide access, no
access to any other bucket. `Resource` is scoped to this one bucket (the bare
ARN, for bucket-level actions like `ListBucket`) and everything inside it
(the `/*` ARN, for object-level actions).

Generate an access key for this user (IAM → Users → your user → Security
credentials → Create access key).

## 3. Enter the credentials

On the **Integrations** page, expand the Amazon S3 card, enable it, and
enter the bucket name, region (e.g. `us-east-1`), access key ID, and secret
access key, then save. Click **Test connection** to confirm the bucket is
reachable before relying on it.

## 4. Pick a folder

Credentials only get you connected — they don't decide where clips land.
Once S3 shows **Connected**, go to the **Storage** tab and use its folder
browser to create or pick the "folder" (S3 prefix) new archives upload into.
See [docs/STORAGE.md](STORAGE.md) for how local vs. archived clip placement
works overall.

## Rotating or revoking access

To rotate the access key, generate a new one for the same IAM user, update
it on the Integrations page, then deactivate (and later delete) the old key
in IAM once you've confirmed the new one works. To revoke access entirely,
delete the IAM user or detach the policy — the app has no other credential
to fall back on.
