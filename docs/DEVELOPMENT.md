# Development guide

## Prerequisites

- Docker with the compose plugin (everything runs in containers via `make`)
- For fast local iteration outside containers: [uv](https://docs.astral.sh/uv/)
  (manages Python 3.14 automatically) and Node 24+

## Everyday commands

| Command | What it does |
|---|---|
| `make dev` | Hot-reloading stack: FastAPI on :8000, Vite on :5173, Postgres :5432, Redis :6379 |
| `make test-backend` | Backend tests in a container against throwaway Postgres/Redis |
| `make test-backend-fast` | Same tests from the local venv (fastest loop) |
| `make test-frontend` | vitest with the coverage gate |
| `make e2e` | Playwright against the seeded production-like stack |
| `make e2e-coverage` | Same, plus an instrumented-frontend coverage report (`e2e/coverage/`) |
| `make e2e-up` / `make e2e-test` / `make e2e-down` | Bring up the seeded stack and leave it running / re-run Playwright against it / tear it down - for iterating on specs without rebuilding each time |
| `make lint` / `make fmt` | All linters / auto-format |
| `make migrate` / `make makemigration m="…"` | Alembic upgrade / new autogenerated revision |
| `make api-types` | Regenerate `frontend/src/api/schema.d.ts` from the backend OpenAPI schema |
| `make secrets` / `make certs` | Generate .env values / self-signed TLS certs |

## Conventions

- **Coverage is a gate, not a goal**: pytest enforces `fail_under = 90`
  (line + branch); vitest enforces 90% on statements/branches/functions/lines.
  Both are a relaxed floor, not the target - new code should still aim for
  ~100% in practice, shipping its tests in the same PR. Playwright/e2e
  coverage (`make e2e-coverage`) is report-only, with no enforced threshold.
- **One Alembic migration per feature PR**, autogenerated then reviewed.
  CI runs `alembic upgrade head && alembic check` to catch model/migration
  drift; the test suite exercises the downgrade path.
- **Typed end to end**: pyright strict on the backend; the frontend consumes
  types generated from the OpenAPI schema — if you change API models, run
  `make api-types` and commit the diff (CI verifies it's in sync).
- **Secrets never in code or logs.** Anything sensitive at rest goes through
  `app/security/crypto.SecretBox`.
- **blinkpy and fastapi-users are only imported inside their adapter
  packages** (`app/blink/`, `app/users/`).

## Workflow

The foundation landed directly on `master`. Every feature from here is a
branch + PR through CI (`.github/workflows/ci.yml`), merged one at a time.
Multi-arch images publish from `master`/tags via `images.yml` to GHCR.

## Version policy

Latest stable everything, verified empirically (registry checks, not memory).
Current deliberate exceptions are listed in
[ROADMAP.md](ROADMAP.md#deferred--watching).
